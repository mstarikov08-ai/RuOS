# RuOS скриншоты и разметка

iOS-овый сценарий: снимок экрана → внизу слева всплывает миниатюра → нажатие
открывает разметку, смахивание влево убирает (снимок уже сохранён).

## Что реализовано

- **Захват + сохранение** (`RuOSScreenshotController`, SystemUI): снимает экран и
  сохраняет PNG в `Pictures/Screenshots` через `MediaStore`.
- **Плавающая миниатюра** (`ScreenshotThumbnailView`): скруглённая карточка с белой
  рамкой и тенью, пружинное появление, авто-скрытие ~5 c, смахивание влево — убрать,
  нажатие — открыть разметку.
- **Редактор разметки** (`RuOSScreenshot`, `MarkupActivity`): ручка, маркер
  (полупрозрачный), палитра цветов iOS, обрезка с угловыми маркерами, отмена,
  «Поделиться», «Готово» (сохраняет правленую копию). Штрихи хранятся в координатах
  битмапа — экспорт в полном разрешении. Глифы инструментов нарисованы на canvas
  (без эмодзи), Golos, тактильный отклик.

## Триггеры

- Тест: `adb shell am broadcast -a com.ruos.action.SCREENSHOT -p com.android.systemui`
- Программно: `RuOSScreenshotController.takeScreenshot()`.

## Что требует доработки на устройстве [device]

- **Захват экрана** вызывает платформенный API
  (`SurfaceControl.getInternalDisplayToken()` + `android.window.ScreenCapture`) через
  рефлексию, чтобы собираться на любом checkout AOSP 14. Это реальный путь вызова, но
  проверить на panther (и отсутствие avc-denials для захвата дисплея).
- **Комбинация Power + Volume-Down**: сейчас захват дёргается методом/броадкастом.
  Чтобы повесить на железную комбинацию, направьте
  `PhoneWindowManager.interceptScreenshotChord` / `ScreenshotHelper` на этот
  контроллер (вместо штатного `TakeScreenshotService`), либо отключите штатный SystemUI
  screenshot, чтобы не было двух миниатюр. Разметка и сохранение от этого не зависят.
